<Callout type="info" title="Automatic configuration">

You can have Ymir configure your project automatically for you by using the [`wordpress:configure`][2] command.

</Callout>

[Elementor][1] is a popular free WordPress page builder that you can use to build beautiful WordPress sites. Ymir makes it easy to support Elementor in your serverless WordPress project. This guide will cover the changes that you need to make.

## Project configuration changes

Below is the environment configuration that `wordpress:configure` adds for Elementor. Replace `environment` with the correct environment name. If your environment already has `excluded_paths`, add the value to the existing list instead of replacing it.

```yml
environments:
  environment:
    cdn:
      excluded_paths:
        - /uploads/elementor/*
```

This stops CloudFront from caching the files that Elementor generates in the uploads directory. It doesn't control browser caching or any other cache in front of your site. Elementor doesn't need any `build.include` paths.

## What `wordpress:configure` changes [#what-wordpress-configure-changes]

`wordpress:configure` uses WP-CLI to scan your local project's plugins. It detects Elementor by the `elementor` plugin directory. When you confirm, it merges the configuration above into `ymir.yml` for the environments you chose.

The command only edits `ymir.yml`. It doesn't install plugins or guarantee that every Elementor version works on Ymir. It appends values to existing lists, removes duplicates and sorts the keys, and rewriting the file removes any comments. Review the changes, then deploy your project for them to take effect.

## WooCommerce product pages [#woocommerce-product-pages]

If you use Elementor with [WooCommerce][3], the Ymir plugin also invalidates the CloudFront cache of published pages built with Elementor product widgets, such as product grids, product archives or loop grids showing products. It does this whenever you save or update a WooCommerce product or variation.

The plugin keeps the list of these pages for up to 10 minutes, and refreshes it when you save or delete a page or an Elementor template. Pages it doesn't detect stay cached until they expire or you invalidate them with the [`environment:invalidate-cache`][4] command. This invalidation follows the same `YMIR_DISABLE_PAGE_CACHING` setting as the [WooCommerce invalidation][5].
