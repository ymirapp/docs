## Why do you need a cache?

To have a high performance WordPress site, you often need a persistent [object cache][1]. A persistent object cache stores MySQL query results in a high performance cache. (Usually Memcached or Redis.) Whenever WordPress needs to perform a MySQL query, it'll check the high performance cache before performing the query.

Ymir lets you create and manage cache clusters using either [Valkey][7] or Redis. You can then use that cluster to power the object cache of multiple WordPress sites.

## Managing cache clusters

You can create a cache cluster using the [`cache:create`][8] command. The command will prompt you to fill in some details about the cache cluster that you're creating, such as its network and type. New cache clusters use Valkey unless you pass `--engine=redis`.

<Callout type="warn" title="Needs a NAT gateway">

Ymir will create a NAT gateway if you create a cache and the network used by the cache doesn't have a NAT gateway already. A NAT gateway bills by the hour and for the data it processes, plus its public IPv4 address and data transfer. Prices vary by region. See the [Amazon VPC pricing page][11] and the [AWS costs guide][12].

</Callout>

```bash
ymir cache:create
```

You can change the type of a cache cluster with the [`cache:modify`][9] command. The type is the only setting that you can change. The cache cluster will become unavailable for a few minutes while the change takes effect.

If you don't need a cache cluster anymore, you can delete it with the [`cache:delete`][10] command. If no other resources use the network's private subnet, you can then remove its NAT gateway with the `network:nat:remove` command.

## Using a cache cluster in a project

Since you can use a cache cluster on multiple projects, you need to configure your project to use one. To do that, you need to update your `ymir.yml` configuration file with the `cache` option. Ymir will then inject the necessary environment variables so that your WordPress site can use the cache cluster.

```yml
id: 1
name: project-name
type: wordpress
environments:
  staging:
    cache: my-cache-cluster
  production:
    cache: my-cache-cluster
```

You'll also need to install an object cache in your WordPress project. You can learn how to do that with [this guide][2].

## Connecting to a cache cluster

Because a cache cluster resides on your network's private subnet, it's not publicly accessible. To connect to it, you'll need to use the [`cache:tunnel`][3] command. This command will create a [SSH tunnel][4] to your [bastion host][5] which allow you to connect to your cache cluster. The network must have a bastion host, the cache cluster must be available, and your computer needs the `ssh` command.

```bash
ymir cache:tunnel my-cache-cluster
```

The tunnel stays open as long as the command is running. Press `Ctrl+C` to close it. While it's open, connect with a Redis-compatible client such as [TablePlus][6] or `redis-cli` using these settings:

| Setting | Value |
| --- | --- |
| Connection type | Redis |
| Host | `127.0.0.1` |
| Port | `6378`, or the port you passed with `--port` |
| Username and password | Leave empty |
| TLS/SSL | Disabled |

For example, with `redis-cli`:

```bash
redis-cli -h 127.0.0.1 -p 6378
```

If port `6378` is already in use on your computer, pass a different one with `--port`. You can't use port `6379` since that's the port of the cache cluster itself. The command prints the local endpoint to use once the tunnel is open.
